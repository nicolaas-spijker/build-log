# 01 — Content Pipeline

Workflow #1 of the SignalRoads Build Log. End-to-end content pipeline: research → writing → review, with direct CMS push.

Companion writeup: see the Build Log post on SignalRoads.

## What this pipeline does

Takes a topic, produces a fully-formed article (TOC, intro, sections, widgets where useful, inbound links, FAQs, schema), pushes it to a CMS, and runs a post-publish lint on the rendered page.

The system has 4 layers:

1. **Brief** — collapses inputs into a structured markdown file the drafter (LLM) consumes
2. **Research** — pulls the data the brief needs: link library, SERP gap analysis, search demand, engagement signals
3. **Writing** — drafts the article, lints at draft time, embeds widgets/tables, pushes to CMS
4. **Review** — fetches the live page, re-runs the lint against the rendered HTML, flags regressions

## How to use it (today)

The two Built scripts run end-to-end. See [SETUP.md](../SETUP.md) for the bootstrap. Once your link library exists, the suggestion flow gives you the highest-leverage component of the pipeline: contextual internal links generated by an LLM rather than hardcoded by hand.

For the rest, read the brief template, read each stub's docstring, and you have the design. Implementations land week by week.
